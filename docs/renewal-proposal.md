# SRC Plus 홈페이지 리뉴얼 제안서

작성 기준: 저장소 `index.html`, `assets_report.css/js`, `build.py`, `member-guide.html` 코드 분석 (2026-11-11).
한계: 배포본(srcplus.vercel.app)과 SRC 본 홈페이지는 이 세션에서 열람하지 못했다. 아래 "SRC 톤"은 **가정**이며 토큰 한 곳(`:root`)만 바꾸면 교체되게 설계했다. 레퍼런스는 기억 기반이므로 URL 방문 확인이 필요하다.

## 1. 현황 분석

### 1-1. 디자인 시스템

| 항목 | 현재 | 문제 |
|---|---|---|
| 서체 | Playfair Display(타이틀·이탤릭 태그라인) + Noto Sans KR + IBM Plex Mono | Playfair는 한글 미지원이라 영문 로고만 세리프로 튀고, "세리프 이탤릭 태그라인 + 모노 대문자 라벨"은 생성형 템플릿에서 가장 흔한 조합이다. 한글 본문 서체도 Noto 기본형이라 개성·밀도가 약하다 |
| 글자 크기 | 마이크로 라벨 0.54~0.62rem (html 15px → **8~9px**) | 가독성 기준(최소 11~12px) 미달. 날짜·태그·통계 라벨이 사실상 읽히지 않는다 |
| 대비 | `--ink-faint #a9abad` on `#f1f2f2` ≈ 2.1:1 | WCAG AA(4.5:1) 미달. 날짜·카운트·placeholder 전부 해당 |
| 색 | 쿨 그레이 + 슬레이트 블루 1색 | 방향은 좋다(절제). 다만 accent가 채도 낮은 중간 명도라 링크·강조의 "신뢰감" 신호가 약하다 |
| 형태 | 전 요소 radius 0, 1px 헤어라인, 점선 배지 | 일관되나 "브루탈리스트 에디토리얼" 클리셰. 장식(스캔라인 배경, Fig. 01 캡션)이 정보 없이 분위기만 만든다 |
| 이미지 | Unsplash 핫링크 스톡 스카이라인 | 출처·맥락 없는 스톡 = AI 티의 주원인. 외부 의존으로 로드 실패 시 빈 패널(실제 렌더에서 확인) |

### 1-2. 필수 기능 점검

| 기능 | 상태 | 비고 |
|---|---|---|
| 목록·카테고리 필터·검색·정렬 | ✅ | 동작 정상 |
| 자동 게시(build.py → REPORTS) | ✅ | **반드시 유지**: `const REPORTS = [...]` 블록 형식에 의존 |
| 글 읽기 흐름(상단바·진행바·목차) | ✅ | 리포트 페이지는 공용 CSS로 일관 |
| 최신 글 강조 | ❌ | 방금 올라온 글과 오래된 글이 같은 무게 |
| 상태 공유(URL) | ❌ | 필터·검색이 URL에 남지 않아 링크 공유 불가 |
| 스크롤 중첩 | ⚠️ | "All" 뷰가 카테고리별 고정 높이 내부 스크롤 → 콘텐츠 발견성↓, 모바일에서 스크롤 충돌 |
| 통계·갱신일 | ⚠️ | "Updated 2025.06" 하드코딩(실제 최신 글은 2026.10) → 신뢰 손상 |
| 모바일 | ⚠️ | 첫 화면 전체를 좌측 소개 패널이 차지, 글 목록은 스크롤 후 노출 |
| 메타·공유 | ❌ | description / OG / favicon / theme-color 없음 |
| 소속·신뢰 신호 | ❌ | 누가 운영하는지(SRC), 어떤 기준으로 쓰는지, 면책·출처 정책 부재 |
| 접근성 | ⚠️ | 필터가 `div`성 버튼+inline onclick, 결과 변경 알림 없음, 포커스 스타일 미정의 |

### 1-3. 구조적 판단
- 좌측 40% 고정 패널은 화면의 거의 절반을 장식에 쓰고, 본문 컬럼은 760px로 제한되어 큰 화면에서 우측이 비는 **비대칭 낭비**가 생긴다.
- 사이트의 핵심 가치는 "리포트 목록"인데, 첫인상에서 목록이 아니라 분위기가 먼저 보인다.

## 2. 개선안

원칙: ① 장식을 빼고 정보로 신뢰를 만든다 ② 기능 계약(build.py·리포트 파일명·meta)은 건드리지 않는다 ③ 톤은 토큰으로 분리한다.

### 2-1. 디자인 시스템
1. **서체 단일화**: Pretendard(한·영 동일 계열) 하나로 통일. Playfair·이탤릭 제거. 모노는 날짜·번호 숫자에만 제한 사용(tabular-nums).
2. **크기 하한**: 최소 12px. 라벨은 대문자+자간 대신 일반 케이스 12~13px.
3. **대비**: 보조 텍스트 ≥ 4.5:1.
4. **색**: 뉴트럴 유지 + 더 깊은 네이비 accent 1색(링크·활성 상태·카테고리 점). 카테고리는 색 대신 라벨/점으로만 구분(색 남발 금지).
5. **형태**: 헤어라인 + 아주 작은 radius(2~4px). 카드 그림자·그라데이션·글로우 없음.
6. **모션**: hover 색 전환과 목록 진입 fade 외 없음. `prefers-reduced-motion` 존중.

### 2-2. 정보구조·기능
1. **상단 헤더 + 압축 인트로**로 전환(좌 패널 제거). 첫 화면에서 곧바로 최신 글이 보인다.
2. **Latest 영역**: 최신 1편을 크게, 나머지는 목록.
3. **전체 뷰는 시간순 단일 목록**(내부 스크롤 제거) + 카테고리 탭(건수 포함, 선택 시 카테고리 설명 노출).
4. **URL 상태 동기화**(`?cat=&q=&sort=`), `/` 키로 검색 포커스.
5. **통계·갱신일 자동 산출**(REPORTS 최신 날짜 기반).
6. **신뢰 신호**: 푸터에 운영 주체(SRC), 작성 원칙(출처 명시·투자 권유 아님) 한 줄. SRC 본 홈페이지 링크 자리.
7. 메타(description/OG/favicon/theme-color), 시맨틱 마크업(`header/main/nav/ul`), 포커스 링, aria-live.
8. 리포트 페이지는 `assets_report.css`의 **`:root` 토큰만** 교체해 홈과 같은 서체·색을 쓰게 한다(본문 구조·클래스 불변).

## 4. 최종 방향 (구현 범위)

- `index.html` 전면 리뉴얼 (REPORTS 블록·`build.py`·워크플로 그대로)
- `assets_report.css` `:root` 토큰 및 폰트 교체
- SRC 톤 확정 시 바꿀 값: `--accent`, `--bg`, `--font-sans`, 상단 로고 마크, 인트로 카피

### 확인이 필요한 것
1. SRC 본 홈페이지 URL 또는 스크린샷 (톤 확정용)
2. SRC의 정식 명칭·링크, 인스타그램 URL (푸터·신뢰 신호용)
3. 인트로 카피 승인 (현재 문구는 초안)
